# Celestial Library — integration handoff

## Scope and running
Standalone React 19 / TypeScript / Vite application. Node 20.19+ or 22.12+ (Vite 7); `npm ci`, `npx tsc --noEmit`, `npm run build`. Serve `dist/` as a static website with `index.html` at the root (for example, `python3 -m http.server 8000 -d dist`). Assets in `public/images/` are required alongside index.html. The standalone build assumes deployment at the web origin root: some CSS URLs are `/images/...`; configure the host's asset base or adjust these before mounting under a subpath. Do not assume `file://` preview or hosting under a subdirectory is supported. The HTML requests Google Fonts; when offline, fallback fonts are used.

No account service, authentication, remote synchronization, server routes or deployment is included. The host platform owns auth, navigation, account state, shared settings, security, consent and merge policy. Notes and highlights are currently local to the browser/device, not synced; browser storage can be cleared.

## Entry points and navigation
- `src/main.tsx` mounts `src/App.tsx` into `#root` with StrictMode. `App` is the standalone composition and stores a local view discriminated union: atrium, room or reader; there is **no URL router** and reader navigation is not deep-linkable.
- `src/components/Atrium.tsx`, `RoomView.tsx`, `BookDetail.tsx`, `LivingTome.tsx`, `Ledger.tsx`, and `LivingPages.tsx` are the primary components; `src/data/library.ts` exports `allBooks`, `getBook`, `rooms`, and catalog helpers. `LivingTome` receives book/chapter IDs, a `LibraryStore`, callbacks and optional initial page/anchor. The host should map its navigation state and URLs to these IDs, validate incoming IDs, and own back/forward behavior. The existing Soul Hub action is only a standalone notice, not a real platform route.
- Catalog types live in `src/data/types.ts`; source data are in `wisdom.ts`, `becoming.ts`, `visionary.ts`, `patterns.ts`, `millennial.ts` and `supplement.ts`. `VerseBlock.lines` contains `Passage {id,text}`. Book IDs are stable across the catalog; chapter IDs are scoped by book; passage UUIDs are immutable and uniquely assigned in source data. Never regenerate IDs on builds or change them when a passage is edited or moved; use new IDs for new passages. Retain tombstone/alias maps for deletions and versions. Changes to passage text require a versioned text/offset migration; exact-quote mismatch currently hides a highlight rather than attaching it to the wrong text.
- Anchor is `{passageId, offset}` with UTF-16 offset into the original passage. Progress/bookmark also have bookId and chapterId; `page` is a transient display/fallback number, not an identifier. Reader reflows by size and maps the anchor into the current spread. Search snippets and page counts are layout-dependent. Existing legacy bookmarks/progress without anchors can only be approximately resolved from their old page number on first open; old viewport dimensions were never stored. Opened legacy progress gains an anchor; untouched legacy bookmarks keep their number until replaced.
- Highlights carry `id, bookId, chapterId, passage, start, end, quote, color, note, updated`; `start/end` are UTF-16 offsets with exclusive end. Rendering intersects the highlight range with each page fragment, including boundary-spanning passages. New selection is limited to one original passage/paragraph at a time. Overlapping highlights render one color per overlap (first match); editing text or deleting a passage requires explicit reconciliation. Ledger notes have independent IDs and optional book/chapter/passage links.

## Persistence and migration
`src/data/persistence.ts` defines `LibraryPersistenceAdapter {load(): LibrarySnapshot; save(snapshot): void}` and `configureLibraryPersistence(adapter)`. Install the adapter **before** mounting `App`. `src/hooks/useLibraryStore.ts` is the sole UI persistence client; snapshot v2 combines `library` (progress, bookmarks, chapter notes, recents, preferences), `highlights`, and `ledger`. Default `localLibraryAdapter` reads/writes the single JSON key `inner-orbit-celestial-v2`.

On first use with no v2 snapshot, it reads `inner-orbit-library-v1`, `inner-orbit-highlights-v1`, and `inner-orbit-ledger-v1`, preserving all three legacy keys. Legacy `v{verse}:l{line}` references are mapped to immutable passage IDs using the shipped edition; unknown references remain unchanged. A v2 snapshot is written in one localStorage operation. Malformed input or storage access failure sets a visible storage error and does not overwrite the old keys; resolve/export user data before retrying. Failed v2 writes are reported and retry on the next state change. No legacy key is deleted automatically. Old page-only positions are approximate, not fully recoverable.

The adapter contract is synchronous because React renders from an immediately available local cache. For a real API, hydrate a cache before mount; implement `load` from cache and `save` as a durable local write plus an ordered, retryable sync queue. Do not perform asynchronous fetches directly inside the current synchronous adapter. Add explicit remote sync/error state, authentication boundaries, account switching isolation, schema versioning, export/deletion/consent, concurrency, timestamps and conflict resolution (including per-record merge and deletes) in the host. `updated` fields are not a complete conflict protocol. Avoid overwriting one device with another full snapshot; handle quota/offline failures and retain local recovery copies. The adapter is module-global; configure once for a mounted tree and remount after account changes.

## Reader interaction and lifecycle
Drag over a page to turn; the visible **Select text** toggle yields gestures to native text selection, then users choose a highlight color. Page buttons remain available while selecting. Keyboard arrows/Page Up/Page Down turn; `B` bookmarks; Escape closes. The UI also retains Alt-drag for desktop selection, but it is not required. Phone layouts show one leaf; tablet/desktop show two. Selection toolbar currently supports one passage at a time. Native iPad Safari selection, VoiceOver and touch behavior require real-device acceptance testing.

Three.js rendering is isolated to `ThreeBook.tsx` and `PageCurl.tsx`; `ArtifactRelief.ts` creates associated scene geometry/materials. Each component owns its renderer and scene. Unmount cancels RAF, disconnects ResizeObserver, removes WebGL context listeners, disposes geometries/materials/textures/renderer, explicitly releases the context, and removes the canvas. Late-arriving cover textures are disposed after unmount. Context loss or inability to create WebGL switches to CSS fallback. The paper curl is spring-damped procedural mesh deformation, not a physical cloth simulation; its temporary sheet text is an approximation. The surrounding HTML remains the accessible selectable reading surface. Starfield and Living Pages cancel their canvas animation loops and listeners in effect cleanup. Actual GPU memory leak profiling across browsers remains outstanding.

System reduced-motion and the reader's animation-free mode disable the reader opening and page turn animation; ambient starfield is static in reduced mode. Living Pages are reader-activated and receive the reader motion-safe setting as well as respecting system reduced motion. Honor account-level settings in the host rather than maintaining conflicting preferences.

## Full-edition import update
`src/data/completeEditions.json` contains the sourced Legge Tao (81 chapters) and Müller Dhammapada (26 chapters, 423 numbered verses, with nine combined verse ranges). Canonical `legge-N` and `muller-N` chapter IDs coexist with the earlier curated chapter IDs appended to each book: existing stored progress/highlights still point to those earlier curated readings and do not silently remap. New edition passage IDs are deterministic UUIDv5 generated from the edition and source position; the committed JSON is the source of truth. Do not regenerate identifiers after reordering content; retain IDs and migrate text/offsets explicitly. `scripts/import-editions.py` requires Python BeautifulSoup with an XML parser and rebuilds from the included source transcriptions; treat it as an editorial build tool, not an application runtime dependency. The Müller 127/128 source correction and excluded notes are documented in CONTENT-RIGHTS.md. Original chapter-specific commentaries remain attached to the curated readings; full-edition chapters explicitly indicate commentary is not yet available.

Latest additions: additional historical texts are generated by `scripts/import-more-editions.py` into `src/data/otherEditions.json`; sources and caveats are in CONTENT-RIGHTS.md. Shelf previews in `public/images/book-previews` are captures of the 3D book models; regenerate them after model or artwork changes. Notes/highlights remain local to the device unless the host integrates persistence.
